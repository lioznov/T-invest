## Короткий независимый замер задержки

Чтобы проверить возможную нагрузку записи, запущен второй приёмник того же публичного EXCHANGE-потока. Он отмечает время получения и держит данные в памяти, записывая отчёт только после окончания. Длительность ограничена 60 секундами; исходные правила и хеши диагностики сохранены до запуска. Архив основного сборщика не изменён, диагностические котировки не подставляются в сигналы или исследовательские сделки.

Первая попытка с запросом идентификаторов через API закончилась ошибкой подключения через 20,75 секунды, до получения рыночных данных: `data/receiver-latency-probe-20261006-180208-091960.json`. Она сохранена, не превращена в успешный тест. Повторная версия `receiver_latency_probe_v2_cached_identity` использовала уже записанные публичные UID/размер лота и проверила реальную потоковую подписку. Проверка сертификатов не отключалась, токен не менялся, приватные операции не запрашивались.

Успешный замер: 21:04:33 — 21:05:33 МСК, 60,05 секунды, 310 сообщений стакана и 46 сделок. Завершён по заданному сроку (`deadline`), не запущен бессрочно. Отчёт: `data/receiver-latency-probe-20261006-180533-482307.json`; связанный протокол проверяется по его SHA-256.

Сопоставлены **92 одинаковых стакана**: совпадают акция, биржевое время, все уровни и объёмы; источник EXCHANGE, согласованность подтверждена. Повторы одной котировки считаются один раз.

| Приёмник / парная разница | Медиана | 95-й процентиль |
| --- | ---: | ---: |
| Второй приёмник без записи во время получения | 0,859 с | 1,120 с |
| Основной сборщик с архивом | 0,858 с | 1,131 с |
| Основной минус второй, для каждой пары отдельно | +0,27 мс | +23,42 мс |

Ни в одной из этих пар задержка не превысила 5 секунд. Для всех 310 сообщений второго приёмника медиана 0,894 с, максимум 1,301 с. В поле парной разницы `negative_clock_difference=31` означает, что основной приёмник иногда получал сообщение раньше второго: это не 31 ошибка часов. Для самих задержек обоих приёмников отрицательных значений нет.

Вывод ограничен этим коротким вечерним окном: заметного преимущества приёмника без записи не наблюдалось. Это **не доказывает**, что запись никогда не создаёт задержки, и не определяет источник прежних длинных пауз. Два сетевых соединения, сервер, локальная очередь и нагрузка не контролировались; сравнение не рандомизировано. 92 из 310 обновлений сопоставились — остальные не используются для причинного вывода. Задержка относительно биржевого времени также зависит от точности локальных часов. Измерение не является тестом прибыльности.

Документация [потока Т-Банка](https://developer.tbank.ru/invest/services/quotes/marketdata) описывает источник стакана и признак согласованности; [FAQ](https://developer.tbank.ru/invest/services/quotes/faq_marketdata/) — объединение типов подписок и ограничения запросов. В замере использована одна ограниченная потоковая сессия, а не обход лимитов API.

## Воспроизведение

```text
python manage.py study_joint --session 20261006-144129-63dd7a53 --phase forward
python manage.py probe_stream_latency --seconds 60 --tickers SBER GAZP LKOH --identity-session 20261006-144129-63dd7a53
python manage.py test dashboard
```

Первый вызов проверяет все пригодные завершённые сегменты окна на момент запуска, поэтому позднее может дать другой промежуточный отчёт. Второй требует настроенного токена и запускает новый ограниченный публичный замер, а не воспроизводит старые рыночные данные. Машинные входы, отчёты и снимки интерфейса локальны и исключены из Git; воспроизведение конкретных чисел требует сохранённых исходных файлов.
